# 케이스 스터디 소스 — 차량 제작업체 홈페이지 (프로젝트 4)

> 케이스 스터디 작성용 내부 자료. 원 저장소는 비공개이며, 포트폴리오에는 **회사명 없이 익명으로 게재**한다.

- 기간: 2026.07 ~ (진행 중)
- 상태: v1 오픈 준비 완료 / 부품관리 확장은 **고객 자료 대기로 미착수**
- 커밋: 64건 (2026-07-27 기준)
- 역할: 1인 전과정 (기획 협의 · 설계 · 개발 · 인프라 · 배포)
- 원 저장소: 비공개 (`dongwoobae/worldengco-website`)

## 익명화 규칙

포트폴리오 표기는 다음을 따른다.

- 회사명·대표자명·사업자번호·전화번호·주소·이메일 **미표기**
- "특장차(목욕차) 제작업체 홈페이지" 수준으로만 서술
- 라이브 링크는 게재 (접속하면 어차피 회사가 드러나지만, 포트폴리오 문서에 검색 가능한 형태로 회사명을 남기지 않는다)
- 스크린샷에 로고·연락처가 크게 노출되면 크롭하거나 블러 처리

## 프로젝트 개요

반려견 목욕차량과 복지(재가노인·장애인) 이동목욕차를 제작하는 업체의 공식 홈페이지. **기존 Wix 템플릿 사이트를 Next.js로 전면 리모델링**한 신규 구축 프로젝트다.

사이트의 1순위 목표는 신규 차량 문의·견적 획득(lead generation)이며, 정보 구조는 반려견/복지 두 제품군으로 갈라지는 듀얼 트랙으로 설계했다.

## 아키텍처

- **Next.js 16 App Router + TypeScript + React 19 + Tailwind CSS v4**
- **Cloudflare Workers 배포** (`@opennextjs/cloudflare`) — D1(DB), R2(이미지), Email Routing(알림), Turnstile(봇 차단)
- **Drizzle ORM + D1(SQLite)**, Better Auth(이메일·비밀번호, admin 플러그인)
- GitHub Actions CI/CD — lint → format → test → build → **마이그레이션 적용 → 배포**

### Vercel이 아닌 Cloudflare Workers를 택한 이유

상업용 사이트라 Vercel Hobby 플랜을 쓸 수 없었다. Workers 무료 티어는 상업적 사용을 허용해 비용 없이 운영 가능하다. 다른 프로젝트(교회·복지센터)는 Vercel을 썼기 때문에, 이 프로젝트에서 처음 엣지 스택을 다루게 됐다.

## 케이스 스터디 소재

### 1. 블록 에디터의 스테이징 저장 전략

중고차량·출고 게시판이 공유하는 문단/사진 블록 에디터.

- 작성 중에는 R2·DB를 건드리지 않는다. 사진은 브라우저 Blob으로만 보관하고, **저장 버튼을 눌렀을 때만** 업로드 → 블록 일괄 교체
- 원칙: **"고아 파일 ≫ 깨진 링크"** — 항상 DB를 먼저 쓰고 R2 삭제는 나중에. 삭제는 r2Key 확보 → 부모 행 삭제(FK cascade) → R2 정리 순서
- 재시도 안전성: `savedId` 불변식 + 업로드 성공 키 기억으로, 중간 실패 후 재시도해도 메타 행이 중복 생성되거나 같은 이미지가 재업로드되지 않는다
- 소유 검증: `{kind}/{parentId}/…` 프리픽스 밖의 키는 저장 거부. 오래된 탭이 보낸 키는 `R2.head()`로 존재 확인 후에만 커밋

### 2. D1 제약과 마주치기 — 바인드 파라미터 100개 한도

블록을 한 번에 insert하려니 D1의 쿼리당 바인드 파라미터 100개 제한에 걸렸다.

- 블록 insert를 20행 청크로 분할
- `db.batch`(암묵 트랜잭션)로 delete + insert를 원자화
- 블록 수 상한 200으로 방어
- 관련 커밋: `aef48ad fix: saveBlocks D1 batch 원자화·청크 insert 및 kind 분기 중복 제거`

### 3. Turbopack ↔ OpenNext 비호환 (실전 제약)

Next 16 기본 빌드(Turbopack) 산출물로 배포하면 런타임에서 `ComponentMod.handler is not a function`으로 500이 났다. 로컬 개발에서는 전혀 드러나지 않고 **배포 후에야** 발견되는 문제.

- 해결: `next build --webpack`으로 빌드하도록 스크립트 고정
- 관련 커밋: `0409b07 fix: Turbopack 대신 webpack 빌드로 OpenNext 런타임 오류 해결`, `935ba03 fix: Cloudflare 워커 빌드 실패 수정 (proxy 미지원·standalone 경로)`

### 4. 이중예약 3중 방어

A/S·교육 예약에서 같은 시간대가 두 번 확정되면 안 된다.

1. 애플리케이션 사전 체크(`hasConfirmedSlotConflict`)
2. **D1 부분 유니크 인덱스** — `UNIQUE(date, hour) WHERE status='confirmed' AND hour IS NOT NULL`
3. 유니크 위반 예외를 catch해 사전 체크와 동일한 사용자 메시지로 매핑

경쟁 조건에서도 DB 레벨에서 최종 차단된다.

### 5. 공휴일 API가 오류에도 HTTP 200을 주는 문제

예약 가능일 판정에 data.go.kr 특일정보 API를 쓰는데, 이 API는 오류 상황에서도 200을 반환한다. 그대로 캐시하면 **잘못된 결과가 24시간 고정**된다.

- `resultCode !== "00"`이면 캐시하지 않고 throw → poison 캐시 방지
- API 키가 없거나 호출이 실패하면 fail-open(공휴일 판정 없이 진행)
- 단위 테스트로 고정: `holidays.test.ts`의 "resultCode≠00 응답 미캐시"

### 6. 보안 경계 설계

- **Turnstile fail-closed** — 시크릿 미설정이면 검증을 통과시키지 않고 실패 처리. 반대로 공개 폼은 sitekey가 없으면 폼 자체를 전화 안내로 대체(사용자를 막다른 길에 두지 않음)
- **rate limit을 D1에 저장** — Workers isolate는 메모리를 공유하지 않아 in-memory 카운터로는 브루트포스 제한이 동작하지 않는다. Better Auth `rateLimit.storage: "database"` + 공개 액션용 자체 D1 슬라이딩 윈도우(10분당 5회), Turnstile 외부 호출 **전에** 차단
- **admin API 표면 축소** — Better Auth admin 플러그인의 위험 엔드포인트(`remove-user`, `set-role`, `impersonate-user`, `ban-user` 등)를 훅에서 차단하고, `create-user`의 role=admin 요청을 거부. 시드 admin 계정 락아웃 방지
- **이미지 프록시 Content-Type 허용목록** — R2에 CLI로 `text/html` 메타를 넣어도 오리진에서 stored XSS가 되지 않도록 webp/jpeg만 통과, 나머지는 `application/octet-stream` + `nosniff`

### 7. E2E 워치독이 시크릿을 날린 사건 (실전 제약)

E2E 실행 시 `.dev.vars`를 백업하고 테스트용 값을 임시 주입한 뒤 종료 시 복원하는 구조였는데, **빈 파일이 백업되어 복원 시 시크릿이 통째로 사라지는 자기영속 루프**를 실제로 겪었다.

- `isUsableDevVars()` 가드 추가 — 빈 파일은 백업 대상에서 제외
- detached 워치독이 `process.kill(pid, 0)`로 부모 생존을 확인(콘솔 창 깜빡임 회피), 부모가 죽으면 복원 + Windows `taskkill /T /F`로 프로세스 트리 정리
- 관련 커밋: `be4beed fix: e2e가 .dev.vars를 빈 파일로 덮어쓰는 문제 차단`, `53b49cc fix: e2e 워치독 생존 확인을 시그널 0 방식으로 교체`, `2d3d857 fix: E2E 워치독 콘솔 창 깜빡임 수정`

### 8. Wix 콘텐츠 이관 스크립트

기존 Wix 사이트의 출고 실적 게시물을 새 사이트로 옮기는 일회성 마이그레이션(~470줄).

- 사이트맵에서 게시물 목록 파싱 → Wix `wix-warmup-data` JSON을 트리 탐색해 본문 추출
- 이미지: 다운로드 → sharp로 EXIF 회전 + webp(q85) 변환 → 매직바이트 재검증 → R2 업로드
- **재개 가능성**: `delivery_posts.source_url` UNIQUE + `ON CONFLICT DO NOTHING`으로 중복 없이 이어서 실행
- 기본 dry-run, 요청 간 5초 지연, 429/5xx 지수 백오프(retry-after 존중), JSONL 진행 리포트

### 9. CI에서 마이그레이션을 배포보다 먼저

`main` push 시 **D1 마이그레이션 적용 → 배포** 순서로 고정했다. 반대 순서면 새 컬럼을 참조하는 코드가 스키마 적용 전에 서빙될 수 있다. 마이그레이션이 실패하면 배포 스텝은 실행되지 않는다.

GitHub 러너가 빌드한 산출물을 업로드만 하므로 Cloudflare는 빌드하지 않는다. 필요한 시크릿은 `CLOUDFLARE_API_TOKEN` 하나뿐.

## 미완 부분 (솔직하게 쓸 것)

- **부품관리 기능** — 고객이 요청했으나 정리된 부품 목록(엑셀)을 아직 받지 못해 미착수. 데이터 구조를 고객 자료 없이 추측해 만들면 재작업이 확정적이라 대기 중
- **오픈 전 잔여 작업** — Turnstile 실키 교체(현재 테스트 키라 봇 차단 미동작), 도메인 DNS 이전 + 커스텀 도메인 연결, Email Routing 활성화

케이스 스터디에서는 이를 숨기지 않고 "고객 의존성으로 블록된 상태"로 서술한다. 자료 없이 추측 설계를 하지 않은 것이 판단이었다는 점을 함께 적는다.

## 케이스 스터디 작성 시점

**2차 릴리스**로 배치한다. 실도메인 연결·오픈 이후에 작성해야 라이브 링크가 증거로 성립한다 (비공개 저장소라 코드 검증이 불가능하므로 라이브 링크가 유일한 증거).
