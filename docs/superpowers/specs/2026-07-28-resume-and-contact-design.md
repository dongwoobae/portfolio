# 이력서 페이지·연락처 개편·공유/측정 기반 설계

작성일: 2026-07-28

## 배경

포트폴리오를 다크 터미널 테마로 재구축한 직후 상태다. 랜딩 1장과 프로젝트 상세 5장이 전부이고 전부 정적이다. 방문자가 와도 (1) 연락할 수단이 `mailto:` 하나뿐이고, (2) 이력서가 없고, (3) 링크를 공유해도 카드가 비어 있고, (4) 어떤 페이지가 얼마나 읽히는지 측정이 없다.

이 문서는 그 네 가지를 메우는 범위를 정의한다. 더불어 콘텐츠에서 발견된 사실 오류 두 건을 선행 과제로 포함한다.

## 목표

- 채용 담당자가 이력서를 웹에서 바로 읽고 A4 1장으로 인쇄할 수 있다.
- 전화번호가 공개 HTML·JS 번들·저장소의 현재 코드 어디에도 남지 않는다.
- 연락처 복사가 방문자의 메일 클라이언트 설정과 무관하게 동작한다. (Gmail 바로가기는 Gmail 사용자를 위한 보조 수단이며, 기본 동작은 클립보드 복사다.)
- 링크 공유 시 프로젝트별 OG 카드가 뜬다.
- 페이지별 방문 수와 유입 경로를 익명 집계로 본다. 개별 방문자를 식별하지는 않는다.

## 범위 밖

잔디(GitHub 기여 그래프) 최근 90일 뷰, favicon 교체, 문의 폼. 별도 작업으로 뺀다.

## Phase 1 — 연락처 개편

### 문제

`mailto:`는 윈도우 데스크톱에서 Outlook을 깨우거나 앱 선택 대화상자를 띄운다. 웹메일 사용자에게는 순수한 방해다. 모바일에서는 정상 동작하지만, 복사 후 붙여넣기가 그보다 나쁘지 않다.

### 설계

`src/components/contact/CopyEmail.tsx` (클라이언트 컴포넌트)

- 클릭 시 `navigator.clipboard.writeText(email)` → 라벨을 2초간 `copied ✓`로 바꾼다.
- 상태 영역에 `aria-live="polite"`를 두어 스크린리더에 복사 완료를 알린다.
- 클립보드 API 실패(권한 거부 등) 시 해당 텍스트를 선택 상태로 만들어 수동 복사를 유도하고, 라벨을 `복사 실패 — 직접 복사하세요`로 바꾼다.
- 보조 링크 `[Gmail]` → `https://mail.google.com/mail/?view=cm&to=<email>`. 이 링크는 수신자 주소와 무관하게 방문자 본인의 Gmail 작성 화면을 연다.

적용 위치

- `src/components/home/SideRail.tsx` — `mail` 행의 `mailto:` 앵커를 교체하고, `phone` 행을 삭제한다.
- `src/app/page.tsx` 푸터 — `mailto:` 앵커를 교체하고, `{site.phone}` 출력을 삭제한다.

### 전화번호 처리

`src/lib/site.ts`의 `phone` 필드를 **삭제한다.** 저장소에 남기지 않는다. 값은 Cloudflare Workers secret `RESUME_PHONE`으로 옮기고, Phase 2의 서버 라우트에서만 읽는다.

`.env` 및 `.env.local`은 건드리지 않는다. 값 주입은 `wrangler secret put`으로 한다.

`site.ts`에 이미 커밋된 전화번호는 git 히스토리에 남지만 되돌리지 않는다. `dongwoobae/portfolio` 저장소가 비공개라 노출 경로가 없다. 히스토리 재작성 비용이 이득보다 크다.

### 공개 이메일 주소

`site.email`을 `dw5817@naver.com`에서 **`dw5817@gmail.com`으로 교체한다.** 실제로 확인하는 주소여야 연락을 놓치지 않는다.

같은 파일의 `repoUrl` 필드는 소비 지점이 없는 사용하지 않는 값이고, 가리키는 저장소도 비공개라 링크로 쓸 수 없다. 이번에 함께 삭제한다.

### 문서 갱신

README의 "클라이언트 상태는 셋뿐입니다 — 히어로 타이핑 진행도, 스크롤 스파이 활성 섹션, 목록 hover 미리보기" 문장에 복사 피드백 상태와 Phase 2의 잠금 상태를 반영한다.

## Phase 2 — `/resume` 페이지와 연락처 잠금

### 방침

이력서 PDF를 별도 파일로 만들지 않는다. `/resume` 라우트를 기존 콘텐츠에서 조립하고 인쇄용 CSS를 붙여, 브라우저의 "PDF로 저장"으로 뽑는다. 파일을 따로 두면 갱신 시 두 곳을 고쳐야 하고 반드시 한쪽이 낡는다.

페이지를 볼 수 있으면 인쇄도 할 수 있으므로 "파일만 잠그는" 설계는 성립하지 않는다. 따라서 **잠그는 대상은 전화번호 하나**로 한정한다. 이력서 본문은 공개하고, 연락처가 채워진 상태는 비밀번호로 연다.

### 콘텐츠

`src/content/resume.ts` 신설. 기존 콘텐츠를 재사용하고 중복을 만들지 않는다.

| 항목 | 출처 |
| --- | --- |
| 경력 | `home.ts`의 `career` 중 재직 2건만 선별 + 회사별 성과 불릿을 이 파일에 추가 |
| 대표 프로젝트 | `home.ts`의 `highlights` + `case-studies.ts`의 `meta[].links` 재사용 |
| 기술 스택 | `home.ts`의 `stackLines` 재사용 |
| 요약 3줄 | 신규 |
| 학력 | 신규 (입학·졸업 연월) |
| 자격증 | 신규 — NCA(2024.08), NCP(2024.08), 컴퓨터활용능력 1급 필기(2022.04) |
| 어학 | 신규 — TOEIC 825 (2022.04) |

`meta.ts`에는 라이브·저장소 링크가 없다. 링크는 `case-studies.ts`의 `meta[].links`에만 있으므로 그쪽을 참조한다.

`home.ts`의 `career`는 재직·교육·학력이 한 배열에 섞여 있다. 이력서는 경력과 학력을 분리해 싣기 때문에, 그대로 가져오면 학력 항목과 중복된다. 따라서 다음과 같이 나눈다.

- `career` 항목에 `kind: "job" | "education"` 필드를 추가한다.
- 이력서의 **경력** 절은 `kind === "job"`인 2건(모바일이앤엠애드, 메디케이시스템)만 쓴다.
- 이력서의 **학력** 절은 `kind === "education"`인 2건(네이버클라우드 과정, 고려대)에 입학·졸업 연월을 더해 쓴다.
- 랜딩은 지금처럼 전체를 순서대로 렌더한다. 표시 결과가 바뀌지 않는다.

`src/content/schema.ts`의 기존 패턴을 따라 zod로 빌드타임 검증한다.

2024년판 이력서(부트캠프 수료 직후)의 구조는 따르지 않는다. "보유 역량 요약"을 앞세운 신입용 구성이고, 대표 프로젝트가 폐쇄된 부트캠프 팀플 3건이며, 재직 경력이 없다. 팀플 3건은 `home.ts`의 `team`이 이미 담고 있으므로 이력서에서는 맨 아래 한 줄씩으로 내린다. Notion 포트폴리오 링크와 velog 링크는 쓰지 않는다.

### 라우트

`src/app/resume/page.tsx` — 서버 컴포넌트, 정적 생성. 랜딩의 좌측 레일 대신 상세 페이지와 같은 중앙 1단 셸을 쓴다.

`generateMetadata`에서 `robots: { index: false, follow: false }`를 설정한다. 재직 중에 이력서가 검색 결과로 뜨는 것을 피하기 위함이다. `src/app/sitemap.ts`에서도 제외한다.

**`noindex`는 접근 통제가 아니다.** 검색 엔진에 대한 힌트일 뿐이고, URL을 아는 사람은 누구나 열람·공유·수집할 수 있다. 따라서 **이력서 본문(경력·프로젝트·학력·자격증)은 완전 공개로 간주하고 작성한다.** 노출되면 곤란한 값은 전화번호뿐이고, 그것만 아래 잠금으로 보호한다.

### 연락처 잠금

`src/components/resume/ContactUnlock.tsx` (클라이언트 컴포넌트)

- 초기 상태: `phone · 🔒` + 비밀번호 입력 필드 + 해제 버튼.
- 제출 시 `POST /api/resume-contact`. 성공하면 응답의 전화번호를 화면에 채우고 입력 UI를 감춘다.
- 실패 시 `비밀번호가 올바르지 않습니다`를 표시한다. 남은 시도 횟수는 노출하지 않는다.
- 해제 상태는 컴포넌트 상태로만 유지한다. 새로고침하면 다시 잠긴다. 세션·쿠키를 두지 않는다.

`src/app/api/resume-contact/route.ts`

- `POST` only. 다른 메서드는 405.
- 요청 본문 `{ password: string }`을 zod로 검증한다.
- **secret은 `getCloudflareContext().env`로 읽는다.** OpenNext Workers에서 `process.env`로는 바인딩된 secret이 잡히지 않는다. 대상은 `RESUME_PASSWORD`와 `RESUME_PHONE` 두 개다.
- 비교는 입력과 정답을 각각 SHA-256으로 해시해 **고정 길이 바이트끼리 상수 시간 비교**한다. 문자열을 직접 비교하면 길이와 일치 위치가 타이밍으로 새어 나간다.
- 성공 시 `200 { phone }`. 실패 시 `401 { error: "invalid" }`. 실패 응답에 힌트를 담지 않는다.
- **모든 응답에 `Cache-Control: private, no-store`를 명시한다.** 이것이 없으면 Cloudflare 엣지나 브라우저가 성공 응답을 캐시할 수 있고, 그 순간 잠금이 무의미해진다. 이 라우트는 `export const dynamic = "force-dynamic"`으로 정적 최적화 대상에서도 뺀다.
- 무차별 대입 방지로 IP 기준 시도 횟수를 제한한다. 초과 시 `429`. Workers Rate Limiting 바인딩은 POP 단위로 동작하고 카운트가 최종 일관성이라 전역 정확도를 보장하지 않는다. 완벽한 차단이 아니라 자동화 속도를 늦추는 것이 목적임을 전제하고, 수단(Rate Limiting 바인딩 또는 Cloudflare WAF 규칙)은 구현 단계에서 실제 동작을 확인해 확정한다. 어느 쪽이든 애플리케이션 코드의 계약(429 반환)은 동일하다.

전화번호는 이 응답 외의 경로로 절대 나가지 않는다. 정적 HTML, JS 번들, sitemap, OG 이미지 어디에도 포함되지 않는다. 클라이언트 컴포넌트에는 전화번호가 상수로 들어가지 않으며, 오직 fetch 응답으로만 주입된다.

### 인쇄 디자인

`@media print` 블록에서만 적용한다. 화면 표시는 사이트의 다크 터미널 테마를 그대로 유지한다.

**원칙 — 종이에서는 터미널 장식을 전부 뺀다.** 화면에서 개성인 요소가 종이에서는 노이즈다. 채용 담당자는 이 문서를 다른 지원자 이력서와 나란히 놓고 읽는다. 읽기 속도를 방해하는 것은 모두 제거한다.

제거 대상: `$ cat resume.md` 형태의 프롬프트 접두사, 커서 블록(`▊`), `~/dongwoobae` 경로 표기, 카드 보더와 배경 박스, 네비게이션, 잠금 입력 UI와 해제 버튼.

**지면**

- A4 210×297mm. 여백 상하 15mm, 좌우 18mm.
- 1장에 맞춘다. 넘치면 대표 프로젝트를 3건에서 2건으로 줄인다.
- `page-break-inside: avoid`를 경력 항목과 프로젝트 항목 각각에 건다. 한 항목이 페이지 경계에서 잘리지 않게 한다.

**참고한 레퍼런스**

사용자가 2024년에 쓰던 「코딩몬스터 표준이력서」 양식을 참고한다. 그 양식의 강점 두 가지를 가져오고, 약점 두 가지는 고친다.

가져올 것 — (1) 섹션 헤더가 컬러 볼드 + 전폭 하단 실선이라 경계가 한눈에 잡힌다. (2) 본문 안의 기술 키워드를 컬러로 강조해 스캔이 빠르다.

고칠 것 — (1) 1열 불릿 나열이라 분량이 2페이지로 늘어난다. (2) 기간이 항목 제목의 괄호 안에 묻혀 시간 축이 읽히지 않는다.

**섹션 헤더**

- 섹션명은 accent 컬러 Bold, 좌측 정렬.
- 바로 아래에 전폭 0.5pt 실선을 깐다.
- 섹션 사이 상단 여백 7mm, 헤더와 본문 사이 3mm.

**본문 레이아웃**

좌측 라벨 열 + 우측 내용의 2열 구조를 전 섹션에 적용한다. 레퍼런스의 1열 나열 대신 이 구조를 쓰는 이유는 A4 1장 목표 때문이고, 부수적으로 경력의 시간 축이 좌측에 정렬돼 흐름이 바로 읽힌다. 랜딩의 경력 섹션이 이미 쓰는 문법이라 화면과 종이의 인상도 이어진다.

- 좌측 열 고정 폭 22mm. 기간이 들어간다. JetBrains Mono.
- 우측 열이 본문. 좌측 열과의 간격 6mm.
- 섹션 헤더의 실선은 두 열을 가로질러 전폭으로 긋는다.

**프로필 사진**

우측 상단, 이름 블록과 같은 행. 폭 26mm의 세로 직사각형. `public/photo/dongwoo_photo.jpg`를 쓴다. 레퍼런스와 같은 배치다.

**타이포**

- 본문은 IBM Plex Sans KR. 기간·URL 등 보조 정보는 JetBrains Mono. 화면과 같은 폰트를 쓴다.
- 이름 18pt Bold / 섹션 헤더 11pt Bold / 항목 제목 10pt Medium / 본문 9.5pt / 보조 8.5pt.
- 본문 행간 1.6.

**색**

- 본문 검정(`#111`), 보조 회색(`#666`), 구분선 연회색(`#ddd`).
- accent 컬러는 **화면 토큰 `--color-accent`(`#7ee2a8`)를 그대로 쓰지 않는다.** 민트색이라 흰 종이에서 대비가 부족해 거의 읽히지 않는다. 같은 색조를 유지하되 명도를 낮춘 진한 초록(`#1a7f4f` 선에서 확정)을 인쇄 전용 토큰으로 둔다.
- accent를 쓰는 곳은 두 군데로 한정한다 — 섹션 헤더, 그리고 본문 안 기술 키워드. 그 외에는 쓰지 않는다. 남용하면 강조가 강조로 기능하지 않는다.
- 흑백 출력 시 accent는 중간 회색으로 떨어진다. 색이 사라져도 Bold와 실선으로 위계가 유지되도록 설계한다. 색에만 의존하지 않는다.
- 배경색과 보더 박스를 쓰지 않는다. 섹션 구분은 실선과 여백으로만 한다.

레퍼런스 하단의 `* designed by Codingmonster TV` 워터마크에 해당하는 요소는 두지 않는다.

**링크**

밑줄과 색을 제거하고 검정 텍스트로 둔다. 다만 프로젝트의 라이브·저장소 URL은 `::after`로 URL 문자열을 병기한다. 종이에서 클릭할 수 없으므로 주소가 보여야 한다.

**전화번호**

해제 후 인쇄하면 포함된다. 해제하지 않고 인쇄하면 그 자리가 비어 출력된다. 잠금 입력 UI 자체는 인쇄되지 않는다.

**검증**

Chrome 인쇄 미리보기로 확인하고, 흑백·컬러 양쪽으로 실제 출력해 본다. 화면 미리보기만으로 판단하지 않는다. 특히 accent 컬러의 종이 대비는 실제 출력물로만 판정한다.

## Phase 3 — OG 이미지

현재 `src/app/layout.tsx`의 `openGraph`에 `images`가 없고, `src/app/projects/[slug]/page.tsx`의 `generateMetadata`는 title·description만 반환한다. 링크를 공유하면 썸네일 없이 텍스트만 뜬다.

`next/og`의 `ImageResponse`로 빌드타임에 생성한다.

- `src/app/opengraph-image.tsx` — 루트 1장. 이름, 역할, 도메인.
- `src/app/projects/[slug]/opengraph-image.tsx` — 프로젝트 5장. `generateStaticParams`로 정적 생성한다.
- 규격 1200×630. 사이트의 다크 터미널 색 토큰을 그대로 쓴다.

**폰트는 `next/font`를 쓸 수 없다.** `ImageResponse`는 폰트 파일의 바이트를 `fonts` 옵션으로 직접 받는다. JetBrains Mono의 woff/ttf 파일을 저장소에 두고 읽어서 넘긴다. 여기서 막히면 시스템 기본 폰트로 떨어뜨리되, 그 경우 카드 디자인을 타이포 의존이 낮은 형태로 조정한다.

빌드 후 생성된 이미지 6장을 실제로 열어 확인한다. 생성 자체가 실패해도 빌드는 통과할 수 있으므로 산출물 확인을 생략하지 않는다.

`/resume`에는 OG 이미지를 두지 않는다. `noindex` 대상이고 공유를 의도하지 않는다.

## Phase 4 — 애널리틱스

Cloudflare Web Analytics를 `src/app/layout.tsx`에 넣는다. 쿠키를 쓰지 않아 동의 배너가 필요 없고, Workers 배포와 정합한다. 토큰은 `NEXT_PUBLIC_CF_BEACON_TOKEN` 환경변수로 주입하고, 값이 없으면 스크립트를 렌더하지 않아 로컬 개발에 영향을 주지 않는다.

## 테스트

### Vitest

- `home.ts`의 하이라이트 slug가 전량 `meta.ts`의 slug 집합에 포함된다 (Phase 0-2 회귀 방지).
- `resume.ts`가 zod 스키마를 통과한다.
- 비밀번호 검증 함수: 정답 통과, 오답 거부, 빈 문자열 거부, 길이가 다른 입력 거부.

### Playwright

- `/resume`가 200으로 뜨고 경력 4건이 렌더된다.
- 초기 상태에서 페이지 어디에도 전화번호 문자열이 없다.
- 오답 제출 후에도 전화번호 문자열이 없다.
- 정답 제출 시 전화번호가 나타난다. (E2E 환경변수로 테스트용 비밀번호를 주입한다.)
- 랜딩과 `/resume`에 `mailto:` 링크가 하나도 없다.
- 복사 버튼 클릭 시 `copied` 피드백이 뜬다.

기존 E2E가 전화번호·`mailto:` 제거로 깨질 수 있으므로 같이 손본다.

## 위험 요소와 대응

| 위험 | 대응 |
| --- | --- |
| 잠금 응답이 어딘가에 캐시되어 전화번호가 새어 나감 | `Cache-Control: private, no-store` + `force-dynamic`. E2E에서 응답 헤더를 직접 검증한다. |
| `ImageResponse`가 OpenNext 빌드에서 실패 | 빌드 스크립트에서 PNG를 미리 생성해 `public/og/`에 두고 정적 참조로 전환한다. |
| 인쇄 레이아웃이 브라우저마다 다름 | Chrome 기준으로 맞춘다. 1장을 넘기면 프로젝트 항목 수를 줄인다. |
| 첫 서버 라우트가 생겨 "DB·인증·API 없음"이라는 단순함이 깨짐 | 라우트를 하나로 한정하고 상태를 두지 않는다. README에 이 예외를 명시한다. |

OpenNext는 Route Handler를 공식 지원하므로 별도 Worker로 분리하는 우회 경로는 상정하지 않는다. `npm run preview`로 Workers 런타임에서 한 번 확인하는 것으로 충분하다.

## 구현 전 필요한 입력

다음 두 덩어리는 코드에서 조립할 수 없다. 구현 단계에서 초안을 작성하고 확정을 받는다.

1. 요약 3줄 — 무엇을 하는 개발자인지.
2. 회사별 성과 불릿 — 메디케이시스템 4~5줄, 모바일이앤엠애드 2~3줄. 가능하면 규모나 건수를 숫자로.

Workers secret 두 개(`RESUME_PASSWORD`, `RESUME_PHONE`)는 배포 전에 주입한다.

## 실행 순서

Phase 0 → 1 → 2 → 3 → 4. Phase 0은 사실 오류 정정이라 단독으로도 먼저 배포할 수 있다. Phase 3·4는 앞 단계와 독립적이므로 순서를 바꿔도 무방하다.
